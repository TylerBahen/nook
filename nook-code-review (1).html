SEO Search visibility issues
High · Must fix No meta description tag <head>

Google uses this as the snippet text in search results. Without it, Google picks arbitrary text from the page — usually something unhelpful. This is the single highest-impact SEO tag missing.

Add inside <head>

<meta name="description" content="Nook is a warm, intentional community platform where you share your life with the people that matter — no algorithms, no ads." />
High · Must fix Lorem ipsum placeholder text in "How it works" .steps

Search engines index and display this dummy text. It actively hurts rankings and credibility. Replace all three step descriptions with real copy before deployment.

Example replacement

<p class="step-desc">Lorem ipsum dolor sit amet...</p> <p class="step-desc">Tell us a little about yourself — your name, a photo, and the topics you care about most.</p>
Medium Missing Open Graph tags <head>

When the URL is shared on Slack, iMessage, Discord, or social media, platforms read Open Graph tags to build a preview card. Without them, the link renders as a bare URL.

Add inside <head>

<meta property="og:title" content="Nook — Your People, Together" /> <meta property="og:description" content="A warm, intentional community for real connection." /> <meta property="og:type" content="website" /> <meta property="og:url" content="https://yournookdomain.com" /> <meta property="og:image" content="https://yournookdomain.com/og-image.png" />
Medium Missing canonical link <head>

Tells search engines which URL is the definitive version of this page. Prevents duplicate content penalties if the page is accessible from multiple URLs (e.g. with/without www, with/without trailing slash).

Add inside <head>

<link rel="canonical" href="https://yournookdomain.com" />
Accessibility Screen reader and keyboard issues
Medium Emoji icons have no accessible labels .feature-icon

Screen readers announce raw emoji descriptions ("house building", "bouquet"). Adding role="img" and aria-label gives assistive tech a clean, intentional label instead.

Current (all four feature icons)

<span class="feature-icon">&#127969;</span> <span class="feature-icon" role="img" aria-label="House">&#127969;</span> <span class="feature-icon" role="img" aria-label="Plant">&#127807;</span> <span class="feature-icon" role="img" aria-label="Handshake">&#129309;</span> <span class="feature-icon" role="img" aria-label="Lock">&#128274;</span>
Medium Logo links have no descriptive label nav · footer

Screen readers will announce these as "link" with no destination context. Add aria-label to both the nav and footer logos.

Nav logo

<a href="#" class="nav-logo">n<span>oo</span>k</a> <a href="/" class="nav-logo" aria-label="Nook home">n<span>oo</span>k</a>

Footer logo

<a href="#" class="footer-logo">n<span>oo</span>k</a> <a href="/" class="footer-logo" aria-label="Nook home">n<span>oo</span>k</a>
Low Nav element missing aria-label <nav>

If the page ever gains a secondary nav (e.g. footer nav), screen reader users won't be able to distinguish them. Label it now.

Fix

<nav> <nav aria-label="Main navigation">
Security Pre-deployment security items
High · Must fix HTTPS must be confirmed on the host Hosting config

Browsers show a "Not Secure" warning on HTTP sites, which immediately destroys trust — especially critical for a platform asking users to sign up. Most hosts (Netlify, Vercel, GitHub Pages) handle this automatically. Verify it is enabled before going live.

Verification checklist

# Confirm these on your host's dashboard: ✓ SSL/TLS certificate issued and active ✓ HTTP → HTTPS redirect enabled (301) ✓ HSTS header set (Strict-Transport-Security)
High · Must fix /login and /signup pages need full security review /login · /signup

These routes are linked from the landing page but not part of this review. Before deployment, confirm the following are implemented on those pages.

Required checklist for auth pages

# Authentication security requirements ✓ Input validation on all form fields (server-side, not just client) ✓ CSRF tokens on all POST forms ✓ Rate limiting on login attempts (e.g. 5 tries, then lockout) ✓ Passwords hashed with bcrypt / argon2 — never plain text ✓ Error messages are generic ("Invalid credentials", not "Wrong password") ✓ Session tokens rotated on login
Low href="#" placeholder links nav · footer logo

Both the nav and footer logo links use href="#" as a placeholder. This causes the page to scroll to the top unexpectedly on click, and is a minor SEO signal issue. Replace with the actual root path before deployment.

Fix

href="#" → replace with → href="/"
